# Sessions Screen Cleanup — Design

**Date:** 2026-05-24
**Cluster:** A (of 4 — see `project_session_ui_brainstorm_clusters.md`)
**Scope:** `components/app-pages/sessions/sessions-screen.tsx`, `sessions-approval-crossref-screen.tsx`, `sessions` table schema, shared icons, new constants module.

## Problem

The sessions screen has three issues:

1. The "No." column shows `s.id.slice(0, 5)` — a UUID slice that is neither human-readable nor stable as a name. Sessions need a real human-friendly identifier (treat it like a name field on the session).
2. The Census Report and Review Sessions buttons lack icons, and one instance (cross-ref desktop) uses the wrong background color (`bg-brand-green` instead of `bg-brand-dark`).
3. The 4-tile desktop stat grid (Reviewed / Submitted / Unfinished / For Review) shows metrics with mixed scope (some user-scoped, some global) — confusing and not useful right now. The subtitle that reuses the same data is also being dropped. Defer "what stats to show" to a later pass.

Additionally, the `Census Report` URL is currently a placeholder local constant duplicated across screens. Centralize it so the URL can be updated in one place. Reserve a slot for `ADOPT_FOSTER_APPLICATION_URL` to follow the same pattern.

## Goal

- Add an auto-incrementing, human-readable `census_no` to every session and surface it everywhere we currently show a UUID slice for a session.
- Add `DocumentIcon` and `EyeIcon` to the shared icon set; wire them into the Census Report and Review Sessions buttons everywhere those buttons appear.
- Normalize all Census Report and Review Sessions buttons to `bg-brand-dark`.
- Delete the desktop stat tiles and the redundant subtitle.
- Create `lib/constants.ts` for app-wide URL constants and migrate `CENSUS_REPORT_URL` consumers to it.

## Non-goals

- Replacement stats (deferred — user will decide later what, if anything, should live where the tiles are).
- Visual redesign of the sessions screen beyond the changes above.
- Changes to manager screen logic beyond replacing any UUID-slice session displays it shares.

## Design

### 1. `census_no` on sessions

#### Schema

Add column to the `sessions` table:

```
census_no INTEGER GENERATED BY DEFAULT AS IDENTITY UNIQUE NOT NULL
```

Drizzle change: add `census_no: integer("census_no").generatedByDefaultAsIdentity().unique().notNull()` (or equivalent identity helper) to the sessions schema.

#### Migration / backfill (option A — manual SQL one-shot)

`pnpm drizzle-kit push` cannot data-migrate. Use the Supabase MCP `apply_migration` to run a single SQL block:

```sql
-- Step 1: add column nullable so existing rows are accepted
ALTER TABLE sessions ADD COLUMN census_no INTEGER;

-- Step 2: backfill in created_at order (id as tiebreaker for stability)
UPDATE sessions
SET census_no = sub.rn
FROM (
  SELECT id, ROW_NUMBER() OVER (ORDER BY created_at ASC, id ASC) AS rn
  FROM sessions
) sub
WHERE sessions.id = sub.id;

-- Step 3: enforce constraints
ALTER TABLE sessions
  ALTER COLUMN census_no SET NOT NULL,
  ADD CONSTRAINT sessions_census_no_unique UNIQUE (census_no);

-- Step 4: attach an identity sequence starting after the current max
ALTER TABLE sessions
  ALTER COLUMN census_no ADD GENERATED BY DEFAULT AS IDENTITY (
    START WITH <max+1>  -- compute from SELECT COALESCE(MAX(census_no), 0) + 1 FROM sessions
  );
```

The `<max+1>` value is computed at migration time. Implementation can either run a small dynamic block (DO $$ ... $$) or do it in two MCP calls. Either works; pick whichever is simpler.

After the migration, regenerate the drizzle schema (or update the schema file by hand) so the Drizzle column declaration matches the DB.

#### Type updates

- `SelectSession` (in `lib/validation/sessions.ts` or equivalent) picks up `census_no: number` from the schema regen.
- No insert-side change required — identity column auto-fills.

#### UI consumers

Replace `s.id.slice(0, 5)` with `s.census_no` in:

- `sessions-screen.tsx`:
  - Mobile see-all table row (currently `(page - 1) * PAGE_SIZE + i + 1` — that is positional, not the session's census number; switch to `s.census_no`).
  - Mobile dashboard recent table row (`s.id.slice(0, 5)`).
  - Desktop dashboard table row (`s.id.slice(0, 5)`).
  - Desktop see-all table row (`s.id.slice(0, 5)`).
- Manager screen (`components/app-pages/sessions/manager-screen.tsx` if present): audit for the same pattern and replace.

Render as plain number (`{s.census_no}`) with the existing `tabular-nums` class for alignment.

### 2. Button icons + dark normalization

Add two outline SVG icons to `components/app-pages/shared/icons.tsx`, matching the 1.5–2 stroke `currentColor` style of the rest of the file:

- `DocumentIcon` — document with horizontal lines (Census Report → Google Doc link).
- `EyeIcon` — outline eye (Review Sessions).

Replace inline emoji/symbols (`⊙`, `📊`) and add icons to instances that currently have none, across:

- `sessions-screen.tsx` mobile see-all action buttons.
- `sessions-screen.tsx` mobile dashboard action buttons.
- `sessions-screen.tsx` desktop header action buttons.
- `sessions-approval-crossref-screen.tsx` desktop header Census Report button (also change `bg-brand-green` → `bg-brand-dark`).

All instances must use `bg-brand-dark` with `text-white`. Icons sit next to the label with a small gap (`gap-1.5` matches the existing pattern).

Consumers:

`ADOPT_FOSTER_APPLICATION_URL` has no consumers yet — declared so future code can import it without each caller redefining a placeholder.

## Risks / Open items

- The mobile see-all view currently displays positional numbering (`(page - 1) * PAGE_SIZE + i + 1`). Switching to `census_no` changes the meaning of that column — now it identifies the session, not its position in the visible page. Confirmed intended: census_no is the session's identifier, not a row counter.
- Identity column with `START WITH max+1` syntax may differ slightly between Postgres major versions. Verify against the project's Supabase Postgres version during the migration step.
- If anything outside the audited screens still slices session UUIDs for display, it'll continue to show UUID slices. Search for `id.slice` against session-typed values during implementation.
