AI SUMMARY

1. The Primary Source of Truth: PostgreSQL Database
   The AGILA App Database (PostgreSQL/Supabase) is the authoritative source of truth for all data. To maintain data integrity and prevent the "feedback loop" errors common in two-way syncs, the system treats the CATalog Google Sheet as a secondary "Living View" rather than a primary data entry point.

2. Access Control & Permission Strategy
   Standard Operation: Google Sheets are set to Read-Only for all volunteers. Data entry is performed exclusively through the Next.js App, which enforces strict Zod validation and Postgres Enum constraints.
   Manager Access: Managers retain "Emergency Edit" permissions on the spreadsheet. While discouraged during normal operation, this allows for immediate data correction without opening the App.
   Failover Case: In the event of critical application failure, the Maintainer will toggle "Editor" permissions for all authorized personnel. The spreadsheet then acts as the temporary failover database to ensure business continuity.

3. The Autonomous Synchronization Engine
   The system employs an hourly (or 10-minute) Self-Healing Sync Worker using the Read-Modify-Write pattern. Each cycle consists of three phases:
   Phase A: Reverse Sync (Reconciliation): The system reads the Google Sheet and compares every row’s timestamp (automatically generated by Google Apps Script) against the Database’s last_updated_at. If a manager’s edit is newer than the database record, the system automatically imports the spreadsheet data into Postgres, validating it through Zod filters to prevent corruption.
   Phase B: Conflict Resolution: The system uses a "Last-Modified Wins" rule with a 5-second safety buffer. If a manual GSheet edit is detected, any pending database tasks in the Sync Queue for that specific entity are superseded and cancelled to prevent overwriting the newer human data.
   Phase C: Forward Sync (Export): All pending database changes (Creates, Updates, Deletes) are batched, deduplicated, and pushed to the Google Sheet. The sheet is then compacted and alphabetized by Nickname to ensure a clean, human-friendly interface for viewers.

4. Audit Logging & Monitoring
   Every automated reconciliation is recorded. If a manual entry in the spreadsheet violates database constraints (e.g., an invalid status or color), the system will:
   Bypass the specific row to prevent database corruption.
   Log the error.
   Dispatch an automated alert via Discord/Slack Webhook to the Maintainer for manual intervention.

5. Prototype & Gradual Adoption Phase
   To ensure the safety of existing AGILA records, the prototype will connect to a Duplicate CATalog Environment.
   Hybrid Testing: Approximately 10 managers/volunteers will use the App
   Census Export: The system will include a specialized export feature to generate Census Session Sheets (Google Docs) that can be used for updating the actual CATalog GSheets the usual way.
